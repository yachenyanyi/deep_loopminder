# PM Agent Skill 设计规范

## 核心定位

PM Skill 不是项目管理流程脚本，也不是工具使用说明。

Skill 的作用是：

> 在特定项目情境下，为 PM Agent 提供额外的判断框架，帮助其做出更可靠的项目治理决策。

Skill 应增强模型判断，而不是替代模型思考。

## 设计重点

一个好的 Skill 应说明：

- 什么时候适用。
- 它要防止哪类典型错误。
- 在该场景下应该关注哪些判断维度。
- 哪些约束值得长期保留。

Skill 应提供经验和约束，而不是固定答案或强制工作流。

## 保持模型自由度

避免：

- 固定输出模板。
- 强制生成大量文档。
- 固定决策路径。
- 把工具调用说明混进治理判断。
- 为了“完整”而堆叠上下文。

允许 PM 根据真实项目状态调整方法。

## Skill 与项目状态

Skill 不主动推动项目。

项目事件、状态变化和不确定性触发 PM 判断；PM 再按需加载最相关的 Skill。

例如：

- 新目标或目标模糊 → `goal-understanding`
- 需要制定推进路线 → `planning`
- 任务或方案失败 → `failure-diagnosis`
- 项目状态发生变化 → `progress-review`
- 计划失效 → `replanning`
- 任务或阶段声称完成 → `acceptance-review`
- 项目或阶段结束 → `retrospective`

## 质量标准

判断一个 Skill 是否值得存在，优先看：

- 是否帮助 PM 做出更好的判断。
- 是否减少一种常见治理错误。
- 是否提供模型不一定会主动想到的经验。
- 是否只在相关场景加载。
- 是否保持足够的推理自由度。

不要用步骤数量、文档长度或流程复杂度衡量 Skill 质量。

## 原则总结

好的 Skill：

- 提供经验，而不是命令。
- 提供约束，而不是限制。
- 提供判断框架，而不是固定流程。
- 让 PM 更像经验丰富的项目负责人，而不是执行脚本。

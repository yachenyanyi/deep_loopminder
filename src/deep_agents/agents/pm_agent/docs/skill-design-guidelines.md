# PM Agent Skill 设计规范

## 核心定位

PM Skill 不是项目管理流程脚本，也不是工具使用说明。

Skill 的作用是在特定项目情境下，为 PM Agent 提供额外的判断框架，帮助其做出更可靠的项目治理决策。

Skill 应增强模型判断，而不是替代模型思考。

## 加载原则

Skill 默认按需检索和加载，不应该预加载所有 Skill。

基础 Prompt 负责：
- PM 的角色定位
- 长期稳定原则
- 判断方向

Skill 负责：
- 特定场景下的专业判断
- 常见错误提醒
- 决策约束

## Skill 设计重点

好的 Skill 应说明：

- 适用场景：什么时候值得加载
- 解决的问题：它帮助避免什么典型错误
- 判断框架：应该关注哪些因素
- 行为边界：哪些做法需要避免

Skill 应提供思考方向，而不是固定答案或强制工作流。

## 保持模型自由度

避免：
- 固定输出模板
- 强制生成大量文档
- 固定决策路径
- 过度细化流程

允许 PM 根据项目实际情况调整。

## Skill 与项目状态

Skill 不主动推动项目。

项目事件和状态变化触发 PM 判断，PM 再决定是否加载相关 Skill。

例如：
- 用户提出新目标 → goal-understanding
- 需要制定路线 → planning
- Worker 返回失败 → failure-diagnosis
- 项目状态变化 → progress-review
- 原计划失效 → replanning
- 功能准备交付 → acceptance-review
- 阶段或项目结束 → retrospective

## 质量标准

一个 Skill 是否有效，应关注：
- 是否帮助 PM 做出更好的判断
- 是否减少典型错误
- 是否提高项目状态可信度
- 是否支持复杂情况处理

而不是：
- 是否包含很多步骤
- 是否生成很多文档
- 是否流程足够复杂

好的 Skill：提供经验而不是命令，提供约束而不是限制，提供判断框架而不是固定流程。

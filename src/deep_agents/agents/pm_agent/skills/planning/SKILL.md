# 计划制定

计划是当前信息下最合理的推进路线，不是之后必须机械遵守的合同。

## 关注

- 当前最重要的未知或风险是什么，是否应先验证它。
- 什么是到达目标的最小可行路径。
- 哪些工作存在真实依赖，哪些可以并行或延后。
- 每个阶段结束时，应该获得什么新证据或能力。
- 哪些节点值得设置验收或重新评估。
- 哪些决策容易回退，哪些决策代价高、应更谨慎。
- 是否存在比“大而完整方案”更小、更快的验证方式。

## 计划粒度

计划应细到足以指导下一阶段行动，但不需要提前决定所有未来细节。

越靠近当前的工作可以越具体；越远、越依赖未知信息的部分应保留调整空间。

## 判断边界

如果目标本身仍不清楚，先回到目标理解，而不是用详细计划掩盖目标问题。

如果关键假设尚未验证，优先安排验证，而不是在假设之上继续扩展大量任务。

## 避免

- 过早设计完整架构或完整任务树。
- 没有验收依据就拆出大量执行任务。
- 平均分配精力，而忽略最关键风险。
- 把计划变化误认为执行失败。
- 为了显得完整而制造没有决策价值的里程碑。

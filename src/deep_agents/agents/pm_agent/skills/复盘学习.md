# 复盘学习 Skill

## 设计理念

复盘不是保存历史，而是从项目经历中提取未来可使用的判断经验。

## 使用场景

- 项目结束
- 重大问题解决后
- 关键决策完成后

## 核心思考

复盘关注：

- 哪些判断正确？
- 哪些假设错误？
- 哪些风险可以提前发现？
- 哪些方法值得复用？
- 哪些行为应该避免？

## 行为约束

- 不保存无价值流水记录。
- 不只记录发生了什么，要理解为什么。
- 不把一次经验机械推广到所有项目。

## 判断标准

有效复盘应该产生未来决策能力。

经验应该帮助 PM：

- 更快识别风险
- 更准确制定计划
- 更早发现问题
- 更好管理类似项目

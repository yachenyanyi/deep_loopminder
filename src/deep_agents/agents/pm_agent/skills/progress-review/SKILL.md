# 进度审查

目标是理解项目真实状态，以及最近变化对整体目标的影响，而不是复述底层执行过程。

## 关注

- 当前项目处于什么阶段
- 最近发生了什么变化
- 当前变化是否推动项目目标
- 哪些任务、阶段或依赖受到影响
- 是否有验证依据
- 是否出现新的风险、阻塞或依赖变化
- 原计划是否仍然有效

## 判断边界

区分：

- 任务执行完成
- 结果验证通过
- 项目阶段完成
- 项目整体完成

这些状态不能互相替代。

## 评估方式

基于已有事实、验证结果和项目目标判断状态，不只根据 Worker 自述。

必要时重新确认目标，判断变化影响范围，再决定是否需要调整计划或触发其他 Skill。

## 避免

- 把任务完成等同于项目完成
- 只根据 Worker 描述更新状态
- 过度关注低层执行细节而忽略目标影响
- 没有证据就把阶段标记为完成

# 进度审查

进度审查回答的是：**项目现在真实处于什么状态，以及接下来是否仍应按原路线推进。**

重点不是复述 Worker 做了什么，而是理解这些变化对项目目标意味着什么。

## 关注

- 当前阶段真正取得了什么结果或证据。
- 最近变化是否让项目更接近目标。
- 哪些任务、依赖、风险或假设因此发生变化。
- 当前是否存在阻塞，阻塞影响局部还是整体。
- 原计划的下一步是否仍然合理。
- 是否出现需要目标澄清、失败诊断或重新规划的信号。

## 状态边界

区分：

- 工作已经执行。
- 执行结果已经验证。
- 阶段目标已经达成。
- 整体项目已经完成。

这些状态不能互相替代。

## 判断依据

优先基于已有事实、验证结果和项目目标，而不是 Worker 自述、任务数量或完成百分比。

证据不足时可以保持状态不确定，不必强行给出精确进度。

## 与验收的边界

进度审查用于项目仍在推进时判断状态和下一步。

当问题变成“这个任务、阶段或项目现在是否可以关闭/交付”，使用 `acceptance-review`。

## 避免

- 把任务完成等同于项目完成。
- 用完成数量代替真实进展。
- 只根据 Worker 描述更新状态。
- 过度关注执行流水而忽略目标影响。
- 发现关键变化后仍机械沿用原计划。

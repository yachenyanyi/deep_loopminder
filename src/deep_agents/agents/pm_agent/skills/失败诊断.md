# 失败诊断 Skill

## 设计理念

失败不是简单的执行错误，而是项目状态发生变化的信号。

PM 不应该看到失败后立即重试，而应该理解失败原因。

## 使用场景

- Worker 任务失败
- 连续尝试无法推进
- 关键路径出现阻塞

## 核心思考

分析失败时关注：

- 失败来自哪里？
- 是目标问题、方案问题、执行问题还是外部限制？
- 是否影响整体计划？
- 当前路线是否仍然合理？

## 行为约束

- 不允许无原因重复尝试。
- 不把所有失败归因于执行 Agent。
- 不忽略失败背后的系统性问题。
- 连续失败时应重新评估方向。

## 判断标准

失败处理的目标不是消除错误，而是恢复项目推进能力。

可能动作：

- 修正任务
- 修改方案
- 更换执行方式
- 调整目标
- 请求人工决策

# 失败诊断 Skill

## Skill定位

帮助 PM 将失败理解为项目状态变化，而不是简单执行异常。

失败是重新判断路线的重要信号。

## 适用场景

- Worker 任务失败。
- 关键路径出现阻塞。
- 多次尝试仍无法推进。
- 当前方案可能不可行。

## 核心判断

分析失败时关注：

- 失败来自目标、方案、执行还是外部限制？
- 当前失败影响哪些目标和计划？
- 原来的假设是否仍然成立？
- 下一步应该修正什么？

## 行为约束

- 不看到失败就立即重试。
- 不默认失败来自执行 Agent。
- 不忽略重复失败背后的系统问题。
- 不让失败停留在表面现象。

## 避免的错误

- 无限重复相同方案。
- 只修复错误，不分析原因。
- 忽略失败对整体项目的影响。

## 判断结果

失败处理的目标不是消除错误，而是恢复项目推进能力。

可能方向：

- 修正任务。
- 调整方案。
- 更换执行方式。
- 修改计划。
- 请求人工决策。

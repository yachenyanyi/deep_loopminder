# 验收判断

验收回答的是：**这个结果现在是否足以被接受、关闭或交付。**

完成不是声明，也不是产物存在，而是目标达到且证据足够。

## 核心判断

- 是否满足原始目标，而不只是完成了后来拆出的任务。
- 是否达到约定或合理推导出的成功标准。
- 是否有可信验证结果支持结论。
- 产物是否实际可用，而不是仅仅存在。
- 用户或业务真正需要的价值是否已经实现。
- 是否还有足以阻止交付的重要缺陷、风险或未知问题。
- 未阻塞交付的遗留事项是否已经明确记录和接受。

## 证据

证据类型取决于项目，不要求固定形式。

可以来自测试、真实运行结果、后端状态、用户行为、数据、人工检查或其他能直接支持目标达成的事实。

优先验证结果本身，不把 Worker 的“完成”状态当成证据。

## 判断结果

验收不必只有“通过 / 不通过”。

根据实际情况可以判断为：

- 已满足目标，可接受。
- 核心目标已满足，但存在已知且可接受的遗留项。
- 证据不足，尚不能确认。
- 存在阻塞性问题，需要继续处理。

## 与进度审查的边界

项目仍在推进、需要判断真实状态和下一步时，使用 `progress-review`。

准备关闭或交付，需要判断结果是否足够时，使用本 Skill。

## 避免

- Worker 说完成就关闭。
- 把任务关闭状态当成最终事实。
- 只检查技术产物，不检查实际目标。
- 为追求“零问题”阻塞已经满足目标的交付。
- 忽略会真实影响交付的重要风险。

# 重新规划

重新规划不是失败，也不是重新开始，而是在现实变化后重新选择最合理的路径。

## 触发判断

优先确认变化是否真的影响路线。

普通任务顺序调整、局部修复或小范围偏差，不一定需要重新规划。

更值得触发重新规划的情况包括：

- 关键技术路线不可行。
- 关键假设被事实推翻。
- 需求、约束或成功标准发生实质变化。
- 风险水平已经改变原计划的合理性。
- 原计划继续执行的成本明显高于重新选择路径。

## 核心判断

- 原路线为什么不再合理。
- 哪些事实或假设发生了变化。
- 项目目标是否改变，还是只有实现路径改变。
- 哪些既有成果仍然有效，可以继续利用。
- 哪些旧任务应停止、暂停、重排或取消。
- 新路线解决了什么问题，又引入了哪些新的未知和风险。
- 新路线应优先验证哪个关键假设。

## 行为边界

- 不为了维护旧计划而忽略现实。
- 不因一次局部失败就推翻整个计划。
- 不无理由改变项目目标。
- 不跳过变化原因，直接生成一套新任务。
- 不静默改变方向；关键变化和新假设应可理解。

好的重新规划不是“重新写一份计划”，而是让路线重新与目标和现实对齐。

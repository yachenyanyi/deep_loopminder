# PM Agent Skill 设计规范

## 核心定位

PM Skill 不是项目管理流程脚本，也不是工具使用说明。

Skill 的作用是：

> 在特定项目情境下，为 PM Agent 提供额外的判断框架，帮助其做出更可靠的项目治理决策。

Skill 应该增强模型判断，而不是替代模型思考。

---

## 加载原则

Skill 默认按需检索和加载。

PM Agent 不应该预加载所有 Skill。

基础 Prompt 负责：

- PM 的角色定位
- 长期稳定原则
- 判断方向

Skill 负责：

- 特定场景下的专业判断
- 常见错误提醒
- 决策约束

---

## Skill 设计重点

一个好的 Skill 应该说明：

### 适用场景

什么时候应该考虑使用该 Skill。

例如：

- 新需求出现
- 项目目标不明确
- Worker 返回失败
- 项目准备验收

---

### 解决的问题

说明这个 Skill 防止什么错误。

例如：

防止：

- 需求未理解就开始执行
- 失败后盲目重试
- Worker 声称完成后直接关闭任务

---

### 提供的判断框架

Skill 应该提供思考方向，而不是固定答案。

例如：

遇到失败时，需要考虑：

- 失败原因
- 对项目目标的影响
- 是否需要改变方案

而不是规定必须执行某个步骤。

---

### 保持模型自由度

避免：

- 固定输出模板
- 强制生成大量文档
- 固定决策路径
- 过度细化流程

允许 PM 根据项目实际情况调整。

---

## Skill 与项目状态的关系

Skill 不主动推动项目。

项目事件和状态变化触发 PM 判断，PM 再决定是否加载相关 Skill。

示例：

用户提出新目标：

→ 可能需要目标理解 Skill

Worker 任务失败：

→ 可能需要失败诊断 Skill

功能完成：

→ 可能需要验收判断 Skill

---

## Skill 的质量标准

一个 Skill 是否有效，应关注：

- 是否帮助 PM 做出更好的判断
- 是否减少典型错误
- 是否提高项目状态可信度
- 是否支持复杂情况处理

而不是：

- 是否包含很多步骤
- 是否生成很多文档
- 是否流程足够复杂

---

## 设计原则总结

好的 Skill：

提供经验，而不是命令。

提供约束，而不是限制。

提供判断框架，而不是固定流程。

让 PM 更像一个经验丰富的项目负责人，而不是一个执行脚本。

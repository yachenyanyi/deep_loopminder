# 失败诊断

失败首先是一条新信息，不应该自动触发“再执行一次”。

## 先判断失败发生在哪一层

可能包括但不限于：

- **执行层**：实现错误、步骤遗漏、操作失误、工具调用失败。
- **环境层**：权限、配置、网络、资源、版本或运行环境问题。
- **依赖层**：外部服务、上游接口、第三方行为或前置条件发生变化。
- **方案层**：当前技术路线或方法本身不可行、代价异常高或无法满足目标。
- **假设层**：计划依赖的关键判断已经被事实推翻。
- **目标层**：当前任务解决的其实不是正确问题，或成功标准本身存在误解。

不要因为错误最后出现在 Worker 或工具那里，就默认根因也在那里。

## 判断信号

关注：

- 这次失败和之前失败是否属于同一种模式。
- 已经确认了哪些事实，哪些仍是猜测。
- 重试会获得新信息，还是只会重复同样条件。
- 局部修复是否足够，还是失败已经影响当前路线。
- 问题会影响单个任务、当前阶段，还是整个项目假设。

## 下一步选择

- 仅在失败具有偶发性、条件已变化或重试能产生新证据时重试。
- 根因明确且局部时，修复当前任务。
- 当前方法不合适时，替换方案。
- 关键假设或路线失效时，进入重新规划。
- 缺少权限、资源或业务决策且无法自主解决时，升级给人工。

## 避免

- 无分析地重复执行。
- 把所有失败归因于执行 Agent。
- 只修复表面错误，不检查是否存在重复模式。
- 在证据不足时过早宣布“方案不可行”。
- 为了保持原计划而忽略已经出现的反证。

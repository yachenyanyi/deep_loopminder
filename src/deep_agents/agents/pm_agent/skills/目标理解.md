# 目标理解 Skill

## 设计理念

目标理解不是需求转任务，而是帮助 PM Agent 判断项目真正要解决的问题。

PM 不应默认接受用户描述中的方案，而应该理解背后的目标、价值和限制。

## 使用场景

当出现以下情况时触发：

- 新项目启动
- 用户提出新需求
- 项目方向发生变化
- 当前目标存在歧义

## 核心思考

在推动项目之前，先理解：

- 为什么要做这个项目？
- 谁会使用这个结果？
- 什么结果代表成功？
- 哪些范围明确不包含？
- 当前有哪些未知和假设？

## 行为约束

- 不要把用户提出的实现方式直接等同于目标。
- 不要在目标明显不清晰时急于拆解任务。
- 不要隐藏关键假设。
- 不确定时应该提出问题，而不是假装理解。

## 判断标准

目标是否已经足够清晰，取决于 PM 是否能够解释：

- 项目为什么存在
- 最终希望达到什么效果
- 如何判断是否成功
- 当前最大的未知是什么

目标理解的目的不是生成大量文档，而是建立正确的项目方向。

# 目标理解 Skill

## Skill定位

帮助 PM 在项目启动、方向变化或目标冲突时，理解真正需要解决的问题。

这个 Skill 不是生成需求文档，而是避免 PM 在错误目标上推进项目。

## 适用场景

- 新项目启动
- 用户提出模糊需求
- 用户描述方案但目标不明确
- 项目方向发生变化
- 多方目标存在冲突

## 核心判断

加载此 Skill 后，PM 应优先判断：

- 为什么需要这个项目？
- 最终希望产生什么价值？
- 谁是目标使用者？
- 什么结果可以证明成功？
- 哪些范围明确不属于当前目标？
- 当前有哪些未知和假设？

## 行为约束

- 不把用户提出的实现方式直接当成目标。
- 不因为需求看似明确就跳过目标理解。
- 不隐藏关键假设。
- 不确定时主动识别缺失信息。

## 避免的错误

- 看到功能列表立即拆任务。
- 过早决定技术路线。
- 把解决方案误认为项目目标。

## 判断结果

目标理解完成后，PM 应该能够解释：

- 项目为什么存在。
- 什么结果代表成功。
- 当前最大的不确定因素是什么。

目标清晰后，才进入下一阶段。

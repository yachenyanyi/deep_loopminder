# 进度审查 Skill

## 设计理念

PM 关注的是项目状态，而不是 Worker 的工作过程。

任务完成不代表项目成功，PM 需要判断这个变化对整体目标的影响。

## 使用场景

- 收到任务反馈
- 里程碑变化
- 项目状态更新

## 核心思考

审查进度时关注：

- 当前距离目标还有多远？
- 已完成内容是否真的产生价值？
- 是否有验证证据？
- 是否出现新的风险或阻塞？
- 下一步最有价值的行动是什么？

## 行为约束

- 不因为 Worker 声称完成就默认完成。
- 不把忙碌等同于进展。
- 不只关注单个任务，要考虑整体影响。
- 不忽略长期目标。

## 判断标准

有效的进度判断必须回答：

- 当前项目状态
- 为什么是这个状态
- 影响是什么
- 下一步应该做什么

PM 的价值是保持项目认知，而不是统计任务数量。

# 进度审查 Skill

## Skill定位

帮助 PM 理解项目当前状态，而不是统计 Worker 完成了多少任务。

项目进度的核心不是活动数量，而是距离目标的变化。

## 适用场景

- 收到 Worker 反馈。
- 任务或里程碑发生变化。
- 需要判断项目是否健康推进。

## 核心判断

审查进度时关注：

- 当前目标距离还有多远？
- 已完成内容是否真正产生价值？
- 是否存在可信验证？
- 是否出现新的风险、阻塞或偏差？
- 下一步最重要行动是什么？

## 行为约束

- 不因为 Worker 声称完成就直接确认成功。
- 不把忙碌等同于进展。
- 不只看单个任务，要理解整体影响。
- 不丢失项目长期目标。

## 避免的错误

- 只统计任务数量。
- 只关注执行过程。
- 忽略完成任务对整体路线的影响。

## 判断结果

有效的项目状态判断应该说明：

- 当前处于什么状态。
- 为什么处于这个状态。
- 对项目有什么影响。
- 下一步应该关注什么。

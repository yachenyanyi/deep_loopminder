# 验收判断 Skill

## 设计理念

完成不是状态，而是经过验证后的判断。

PM 不应该把 Worker 的完成声明直接等同于项目完成。

## 使用场景

- 任务完成
- 阶段结束
- 项目准备交付

## 核心思考

验收时关注：

- 是否满足最初目标？
- 是否达到成功标准？
- 是否有可靠验证？
- 是否存在影响交付的问题？
- 用户真正需要的价值是否实现？

## 行为约束

- 没有证据不要确认完成。
- 不只检查代码存在，而检查目标是否达成。
- 不因为任务关闭就认为项目结束。

## 判断标准

真正完成意味着：

- 目标得到满足
- 结果可验证
- 风险可接受
- 后续行动明确

验收的目的不是结束任务，而是确认项目价值已经产生。
